# dashboard-metrics endpoints

Bearer-token-authenticated, read-only HTTP surface exposing per-user
LiteLLM usage in a shape suited to external dashboards. Reads directly
from `LiteLLM_DailyEndUserSpend`, which the proxy's background writer
refreshes every ~10–15 s (`PROXY_BATCH_WRITE_AT = 10` in
`litellm/constants.py`).

## Routes

| Method | Path | Purpose |
|---|---|---|
| GET | `/dashboard-metrics/users` | KPIs, trend, model mix, per-user rows, coverage |
| GET | `/dashboard-metrics/pricing-gaps` | Models observed with `spend = 0` so the admin can patch pricing |
| GET | `/dashboard-metrics/health` | Rollup freshness check |

All routes require `Authorization: Bearer <DASHBOARD_METRICS_TOKEN>`.

## Configuration

**Env var:** `DASHBOARD_METRICS_TOKEN`

Set to a strong random string. If unset, every request to
`/dashboard-metrics/*` is rejected with 401 — fail-closed, so a
misconfigured proxy cannot accidentally expose metrics.

Generate one with:

```bash
openssl rand -hex 32
```

This token is intentionally **separate** from the LiteLLM virtual-key
system and the master key: the caller is external, has no LiteLLM-user
identity, and rotating its token should not require touching the
virtual-key or master-key systems.

## Identity model

Per-user attribution relies on the OpenAI-standard `user` field in each
request body. The proxy's pre-call hook
(`litellm/proxy/litellm_pre_call_utils.py:2144`) copies that field to
`end_user_id`, which the daily rollup keys on. The response renames it
to **`email`** on the way out, on the convention that callers attach the
user's email in that field.

## Example usage

```bash
TOKEN=$(openssl rand -hex 32)
# ... set DASHBOARD_METRICS_TOKEN=$TOKEN in the proxy env, restart proxy ...

# 1. Per-user metrics for the last 7 days
curl -s \
  -H "Authorization: Bearer $TOKEN" \
  'http://localhost:4000/dashboard-metrics/users?from=2026-10-30&to=2026-11-06&granularity=day' \
  | jq .

# 2. Which models are observed but have no pricing (spend=0 with successful requests)
curl -s \
  -H "Authorization: Bearer $TOKEN" \
  'http://localhost:4000/dashboard-metrics/pricing-gaps?from=2026-10-30&to=2026-11-06' \
  | jq .gaps

# 3. Freshness check — should return "ok" with rollupFreshSec < 60 on a live proxy
curl -s \
  -H "Authorization: Bearer $TOKEN" \
  http://localhost:4000/dashboard-metrics/health \
  | jq .
```

## Response shape

Response bodies are generated by the Pydantic models in `schemas.py`.

Noteworthy fields in `/users`:

- `window` — echoes the request range and granularity (`{from, to, granularity}`).
- `kpis` — a dict of `{cost, activeUsers, requests, tokens, avgLatencyMs}`,
  each shaped `{value, deltaPct}`. `deltaPct` is `null` when the previous
  equal-length window had zero of that metric (no prior baseline to
  compare against).
- `users[].costSource` — one of:
  - `"litellm"` — cost came from LiteLLM's own calculation.
  - `"estimated"` — reserved for future caller-side fallback (currently unused).
  - `"unknown"` — the user had requests but spend was `0` across the board
    (usually means pricing is missing for the models they used; see
    `/pricing-gaps`).
- `coverage.requestsWithUnknownCostPct` — percentage of requests in the
  window with `spend = 0`. Useful to surface a "cost data may be
  incomplete" indicator when non-trivial.

## Response shape — /pricing-gaps

A row appears in `gaps[]` iff, across the window, the model has at least
one successful request AND the sum of its `spend` is exactly `0.0`. Each
entry includes `observedRequests` and `observedTokens` so the admin can
prioritize which pricing entry to add first.

Fix a gap by adding the model to `proxy_config.yaml`:

```yaml
model_list:
  - model_name: <alias>
    litellm_params:
      model: <provider>/<real-model>
      input_cost_per_token:  0.000001
      output_cost_per_token: 0.000002
```

Or dynamically via `litellm.register_model({...})` at runtime.

## Response shape — /health

```jsonc
{
  "status": "ok" | "stale" | "no-data",
  "rollupFreshSec": 12,          // seconds since MAX(updated_at); null if no rows
  "checkedAt": "2026-11-06T10:23:11.521Z"
}
```

`status` is `"ok"` when `rollupFreshSec <= 300` (5 min), `"stale"` above
that, `"no-data"` when the table is empty.

## Tests

```bash
pytest tests/test_litellm/proxy/dashboard_metrics_endpoints/ -v
```

Tests mock the Prisma client and install a fake `litellm.proxy.proxy_server`
module in `sys.modules`, so the suite runs fast and without a real DB.
